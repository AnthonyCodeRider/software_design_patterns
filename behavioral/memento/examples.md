# Examples

## Python standard library - unittest.mock

- [\_patch.**enter** / \_patch.**exit**](https://github.com/python/cpython/blob/main/Lib/unittest/mock.py) - Each `_patch` object returned by `mock.patch(...)` is a Caretaker/Memento hybrid guarding the patched object, which plays the Originator. `__enter__` resolves the attribute's current value via `get_original()` and stashes it in `self.temp_original` (recording in `self.is_local` whether it lived directly in the target's `__dict__`) before overwriting the attribute with the mock - that stashed value is the memento, meaningful only to the `_patch` instance itself. `__exit__` uses `self.temp_original`/`self.is_local` to either `setattr` the original value back onto the target or `delattr` the attribute entirely if it did not exist beforehand, restoring the target to its pre-patch state - the save/restore contract of Memento expressed as a context manager.

## SQLAlchemy

- [SessionTransaction.\_take_snapshot / SessionTransaction.\_restore_snapshot](https://github.com/sqlalchemy/sqlalchemy/blob/main/lib/sqlalchemy/orm/session.py) / [Session.begin_nested](https://github.com/sqlalchemy/sqlalchemy/blob/main/lib/sqlalchemy/orm/session.py) - `Session` is the Originator whose identity map and `_new`/`_dirty`/`_deleted` object sets mutate as application code does work. Calling `Session.begin_nested()` opens a SAVEPOINT-backed `SessionTransaction` whose `_take_snapshot()` captures those sets into its own `_new`/`_dirty`/`_deleted`/`_key_switches` attributes - a Memento of everything that changed since the savepoint began. The `SessionTransaction` chain (linked via `_previous_nested_transaction`) is the Caretaker; calling `rollback()` invokes `_restore_snapshot()`, which expunges newly-added objects, reverts deleted ones, and restores prior identity-map keys, rolling the Session's state back to the snapshot without the Session needing to know how that snapshot is structured internally.

## Django

- [MigrationExecutor.\_migrate_all_backwards / MigrationExecutor.unapply_migration](https://github.com/django/django/blob/main/django/db/migrations/executor.py) - While applying a migration plan forward, `MigrationExecutor` mutates a single `ProjectState` (the Originator) one `state_forwards()` call at a time. Before running each migration slated for later reversal, `_migrate_all_backwards()` records the current `ProjectState` into a `states` dict keyed by migration - each entry is a Memento capturing the exact schema state that existed right before that migration was originally applied. That `states` dict is the Caretaker's history; when the plan is reversed, `unapply_migration(state, migration, ...)` is handed the matching saved `ProjectState` and runs `migration.unapply(state, schema_editor)` against it, reconstructing the pre-migration schema instead of recomputing it from scratch.
